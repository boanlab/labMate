# AI 멘토

학생이 회의록·연구노트·세부업무·목표를 쓰는 자리에서 바로 봐 주고, 밀린 일을 먼저 짚어 주는 선택 기능입니다.
연구실 업무를 굴리는 것을 넘어, 학생이 실무에 나가기 전 업무 습관을 익히게 하는 것이 목적입니다.

**기본으로 모두 꺼져 있습니다.** 관리자가 OpenRouter 키를 넣고 하나씩 켜야 동작하며, 키가 없으면
멘토 버튼과 카드는 화면에 나타나지 않습니다. 나머지 기능은 그대로 씁니다.

## 켜는 방법

1. [openrouter.ai](https://openrouter.ai) 에서 API 키 발급
2. 관리자 화면 › 환경설정 › **AI 설정** 에 키 입력 — `.env` 나 파일에 두지 않습니다
3. 같은 화면에서 쓸 기능을 켜고, 모델과 월 상한을 정합니다

## 기능

**학생**

| 기능 | 내용 |
|---|---|
| 글 점검 | 연구노트·회의록·업무·목표를 쓰는 자리에서 판정과 고칠 점을 준다 |
| 주간 회고 | 한 주 활동을 모아 회고 초안을 만든다 |
| 학기 목표(OKR) | 무엇이 얼마나 되면 달성인지 숫자로 적게 하고 달성률을 보여 준다 |
| 상시 대화 | 지금 보고 있는 화면을 함께 보며 답한다 |

**지도교수**

| 기능 | 내용 |
|---|---|
| 지도철학 | AI 가 교수와 대화하며 연구·교육·실무 철학을 모으고, 승인한 지침이 학생 지도의 근거가 된다 |
| 지도 현황 | 누구를 먼저 챙겨야 하는지 한 화면에서 본다 |
| 능동 감독 | 주간보고가 밀리거나 마감이 지났는데 갱신이 없으면 멘토가 먼저 짚는다 |

능동 감독을 교수가 아니라 멘토가 맡는 이유는, 같은 지적이라도 지도교수에게서 반복해 나오면
학생이 위축되기 때문입니다.

## 응답 품질

- 판정(`충분`/`보통`/`미흡`)을 먼저 선언하고 그 개수만큼만 지적합니다 — 잘 쓴 글에 억지 지적을 붙이지 않도록
- 학생 말투가 아니라 회사·연구소에서 쓰는 문체로 답합니다
- 두루뭉술한 표현은 수치·날짜·주체를 넣어 다시 쓰도록 유도합니다
- 없는 수치·커밋 해시·버전을 지어내지 않고, 입력에 있는 값을 "없다"고 잘못 지적하지 않습니다
- 모델이 내부적으로 거치는 추론 과정은 학생에게 보여 주지 않습니다 — 최종 답변만 화면에 올립니다

기준은 시나리오 15개·규칙 154개로 회귀에서 검증합니다(`qa/scripts/mentor-bench.mjs`,
합격선은 [`qa/scripts/mentor-reference.md`](../qa/scripts/mentor-reference.md)).

## 비용

기본 모델 `anthropic/claude-haiku-4.5`, 월 상한 **$5**(관리자 화면에서 변경). 상한에 닿으면 호출을 멈추고
"이번 달 AI 사용 한도를 다 썼습니다"라고 안내합니다 — 다른 기능에는 영향이 없습니다. 사용량은 관리자
화면에서 기능별로 볼 수 있습니다.

## 키 취급

| 항목 | 처리 |
|---|---|
| 저장 | `JWT_SECRET` 에서 파생한 키로 암호화(Fernet)해 `mentor_secrets` 에 보관 |
| 조회 | 평문은 어떤 API 로도 나가지 않는다. 화면에는 앞 8자·뒤 4자만(`sk-or-v1••••••cdef`) |
| 권한 | 등록·변경·삭제 모두 관리자만 |
| 백업 | 관리자 화면 백업에 mentor 서비스는 들어가지 않는다 — 키가 백업 파일로 새지 않도록 백업 라우터를 붙이지 않았다. CLI `make backup` 에는 암호화된 상태로 포함된다 |
